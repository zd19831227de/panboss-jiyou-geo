最快打开方式

macOS 推荐：直接双击项目文件夹里的：

启动GEO运营系统.command

需要停止系统时，双击：

停止GEO运营系统.command

Windows 试装时，双击：

启动GEO运营系统.bat

如果双击打不开，再用终端复制这两行：

cd /path/to/GEO运营系统 python3 start_services.py

然后打开网页：

http://localhost:5173

登录账号：

admin / admin123
当前版本已经补了 Windows 启动器和桌面壳骨架，但 Windows 还属于技术试装阶段，不算正式商业交付验收。

Windows试装：现在能测什么，不能测什么

现在可以测试

  • 项目能不能解压。
  • `启动GEO运营系统.bat` 能不能启动。
  • 前端 5173 和 API 8770 能不能打开。
  • 证据目录、日志目录能不能自动生成。
  • Chrome 或 Edge 路径能不能识别。

现在不要直接当正式交付

  • Windows 端还没做全平台真机发布闭环验收。
  • 桌面壳 `desktop-shell/` 只是骨架，不是最终安装包。
  • 复制到 Windows 后先做技术试装，再做商业验收。
压缩包里如果看到 `__MACOSX`，那不是项目本体，可以删。真正项目目录是 `GEO运营系统`。
Windows 现在是技术试装，不是正式商用封装版。桌面壳 `desktop-shell/` 只是后续封装骨架。
3

电脑重启后怎么恢复

1

启动系统

终端运行 `python3 start_services.py`，看到前端 5173 和 API 8770 都正常。

2

打开网页

浏览器进入 `http://localhost:5173`，用 `admin / admin123` 登录。

3

检查三平台

进入“系统设置”，豆包、千问、元宝如果不可用，点“打开登录”。

4

运行自检

三个平台分别点“运行自检”。自检有回答和截图，才算能做真实监测。

重启会关闭浏览器进程，但不会删除登录态。平台要求验证码时，需要人工处理。
当前运行目录、日志目录、证据目录已改成跨平台口径。新日志默认写入系统用户目录，不再强依赖旧 `/tmp` 目录。
浏览器登录态会优先复用旧 `~/.geo-ops-browser`，升级版本后不会自动清空原来的登录状态。
4

系统设置：先看系统能不能跑

你要看什么

  • 后端状态：必须运行中。
  • Worker 状态：必须运行中。
  • 验证码服务：Capsolver 是否已配置。
  • 豆包、千问、元宝：是否可用。

你要点什么

  • “刷新状态”：重新读取真实状态。
  • “打开登录”：打开固定浏览器登录平台。
  • “运行自检”：验证平台能否真实提问并返回结果。
  • “运行每日扫描/全量扫描”：提交真实监测任务。

AI 监测端口

豆包 9321，千问 9322，元宝 9323。

发布端口

website 9521，携程 9522，百家号 9523，搜狐 9524，知乎 9525，小红书 9526，抖音 9527，头条 9528。

运行自检
系统设置是第一站。这里不通过，后面的监测和发布都不要开始。
豆包、千问、元宝的登录态目录会复用旧目录。升级版本后不会自动清空原来的浏览器登录态。
5

品牌管理：先把品牌建好

用途

品牌是所有监测和运营动作的主档案。没有品牌，关键词、监测、内容和成绩单都无法形成闭环。

怎么用

点“新增品牌”，填品牌名、官网、自有域名、竞品、简介，保存后确认列表出现。

怎么验真

保存后刷新页面仍存在，才算真实写库。后续关键词选择时能选到该品牌。

6

关键词库：用户会怎么问 AI

分类意思例子
品牌词直接包含品牌名或酒店名某某国际大酒店
产品词具体房型、服务、卖点江景房、亲子房、早餐、停车
行业词行业通用搜索需求城市酒店推荐、商圈住宿
长尾词更像真实用户提问市中心步行街附近适合情侣住的高层景观酒店

AI 状态怎么看

  • 已验证引用：AI 提到品牌，并且有来源链接。
  • 未验证引用：AI 提到品牌，但没有来源链接。
  • 未引用：AI 没提到品牌。
  • 待监测：还没跑过。

搜索按钮做什么

按品牌、分类、AI 状态筛选关键词。它不等于跑 AI 检测，只是查关键词库。

AI监测中心：跑真实检测

1

选择品牌

先选你要检测的品牌。

2

选择关键词

勾选一个或多个关键词。

3

选择平台

豆包、千问、元宝，或 AI 三平台一起跑。

4

提交任务

等待任务完成，再查看回答、截图、来源链接和失败原因。

没有来源链接的“提到品牌”不能算已验证引用，只能算未验证引用。

数据中心：看结果是否有证据

日/周/月

切换不同时间范围，看趋势变化。没有新增数据时应显示无变化。

品牌筛选

只看某一个品牌的数据，适合单客户汇报。

证据完整率

重点看来源链接、截图、原始回答是否齐全。

运营大屏：给老板看整体状态

监测概览

看总监测数、引用数、验证引用数、失败数。

平台状态

看豆包、千问、元宝是否正常。

来源生态

看 AI 更常引用哪些网站，再反推内容发布方向。

10

运营中台：从监测到内容生产

1

生成运营关键词

根据品牌资料生成用户会问的问题。

2

采纳为关键词

把有价值的问题加入关键词库。

3

生成内容

系统产出内容草稿，不代表成品，必须人工审核。

4

上传图片素材

图文平台必须有真实图片。携程、知乎等平台会校验封面或正文图片。

5

质量检查和审核

审核通过后，才能进入发布任务。正文不能带 URL 链接，图文内容建议保留自然 emoji 和正常排版。

6

创建发布任务

选择已绑定账号的平台，点击“建发布任务”，再运行 RPA 草稿填充。

当前内容生产页面的产出是运营草稿，不是无需审稿的最终成品。真正发布前必须人工复核平台规范、字数、图片尺寸和违规词。
11

发布闭环：系统辅助，人工确认

平台当前状态用户要做什么
官网/落地页已接入生成页面后人工上线，回填 URL。
知乎已闭环人工登录账号，系统填标题、正文和封面。发布后系统回捞知乎公开 URL，并验真截图、HTML、摘要。
携程旅拍已闭环系统打开携程内容中心，RPA 填标题、正文、图片、时间、地点、声明。人工点发布，审核通过后用携程 C 端公开 URL 验真。
头条 / 搜狐 / 小红书已有闭环样本系统已有真实闭环样本和三件套，但仍建议每次按真实页面复核。
抖音有历史样本，当前需重做历史任务 339 已如实降级失败，不再冒充通过。后续需重新发一条新任务再闭环。
百家号可做草稿和工作流测试工作流门已通过，但 Windows 端和正式生产还要继续做真机验收。
公众号/西瓜/企鹅禁用当前不作为优先平台。
1

运行 RPA

系统只负责打开固定浏览器、进入固定发布页、填草稿和保存证据。

2

人工最终发布

外部平台最后的“发布”按钮由人工确认，避免误发、封号和平台风控。

3

回捞公开 URL

知乎用公开文章页验真；携程旅拍用携程 C 端公开详情页验真，不用内容中心后台详情页冒充。

4

三件套验真

必须同时有公开 URL、截图证据、HTML 原始证据、摘要证据，任务才会变成 published。

系统不会伪装发布成功。没有公开 URL 或三件套不完整，就不会计入发布闭环。
携程旅拍示例：内容中心显示已发布后，要去携程 C 端页面验真，例如 `https://m.ctrip.com/webapp/you/community/detail?articleId=作品ID`。
抖音当前不能沿用历史 task339 当成功案例。它已被降级为失败记录，后续必须重新发新任务、重新回捞 URL、重新生成三件套。

常见问题

网页打不开

先运行 `python3 start_services.py status`。如果 5173/8770 未运行，重新启动系统。

后端离线

终端运行 `python3 start_services.py`，再刷新系统设置。

AI 没结果

先去系统设置，检查平台登录态和运行自检。

没有引用链接

不能算已验证引用，只能算未验证引用。

发布按钮不能点

检查内容是否审核、平台是否 tested/active、账号是否绑定。

携程已发布但没闭环

内容中心后台详情只能证明已发布。必须找到携程 C 端公开页，系统验真通过后才算闭环。

证据打开是空白

优先看 API 端口 `http://localhost:8770/artifacts/...`。前端 5173 只负责页面展示。

终端不能粘贴

运行 `source ~/.zshrc`，或者重新打开终端。

复制到 Windows 后能不能直接商用

不能直接下结论。当前只适合先做技术试装：能启动、能打开、能识别浏览器、能生成日志和证据目录。

移动硬盘解压后多了 __MACOSX

这是 mac 压缩包附带目录，不是项目本体，可以删。

移动硬盘复制不了

如果硬盘是 NTFS，mac 多数情况只能读不能写。换 exFAT，或先复制到本机再转存。

为什么会有两个端口

5173 是前端页面，8770 是本地 API。前端所有按钮、数据、证据文件都要通过 8770 调用。
